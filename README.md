# 本地预约接口断言与异常场景测试

使用 Postman 测试本地预约服务，覆盖正常预约流程、
输入校验、鉴权异常和不存在的预约。

## 启动服务

在项目根目录打开终端，执行：

```powershell
python .\local-api\server.py
```

服务地址：http://127.0.0.1:8000

运行请求时保持终端打开。
服务重启后，需要重新获取 token 和创建预约。

## 配置 Postman

使用本地项目文件夹中的集合“预约接口测试”，在右上角选择环境“本地预约服务”。

| 环境变量 | 值或用途 |
|---|---|
| `base_url` | `http://127.0.0.1:8000`，末尾不加 `/` |
| `username` | `admin` |
| `password` | `password123` |
| `token` | 成功鉴权后由响应脚本保存 |
| `booking_id` | 创建预约后由响应脚本保存 |

Collection 使用 No Auth。需要有效凭证的更新、删除请求在 Headers 中填写 `Cookie: token={{token}}`；JSON 请求使用 `Content-Type: application/json`。

鉴权异常中的“未携带token”请求不启用 Cookie Header，并清除该地址可能自动发送的缓存 Cookie；“token无效”请求使用 `Cookie: token=invalid_token`。资源不存在的更新、删除请求使用有效 token。

## 运行测试

1. 启动服务，保持终端打开。
2. 选择“本地预约服务”环境，分别用 Runner 运行正常流程、输入校验、鉴权异常、资源不存在四个文件夹，迭代次数设为 1。
3. 鉴权异常按 13 个请求的顺序运行：准备有效 token 和预约、查询原始数据、错误密码请求、异常更新与删除及各自后续查询，最后清理预约。
4. 资源不存在按 6 个请求的顺序运行：获取有效 token → 创建预约 → 成功删除 → 查询不存在编号 → 更新不存在编号 → 删除不存在编号。
5. 检查各请求断言是否通过。异常请求的 400、401、403、404 均按各自用例判定。

具体顺序和输入内容见 [测试用例](docs/TEST_CASES.md)。准备步骤之间保持服务运行；资源不存在分类在成功删除后保留 `booking_id`，后续三个请求使用同一个已删除编号。

## 已完成的检查

- 正常预约的创建、查询、姓名筛选、更新与删除，检查状态码、返回字段及变量保存。
- 必填字段缺失、字段类型错误和 JSON 格式错误，检查 400 及对应错误说明。
- 错误密码、缺少 token、无效 token，检查 401 或 403；异常更新或删除后再次查询，确认原数据和预约仍存在。
- 携带有效 token 访问已删除的预约，检查查询、更新和再次删除均返回 404。
