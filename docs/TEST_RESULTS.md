- 错误密码返回 401 和 `Bad credentials`，响应没有 token 字段。

- 操作前与每次被拒绝的操作后均查询预约编号 3。五次查询均返回 200，姓名 Alex Learner、价格 200、订金状态 true、入住退房日期均符合原始数据。

- 两个更新请求使用完整 JSON；无效凭证填写在 `Cookie: token=invalid_token` 中；两个删除异常请求均配置状态码与错误说明断言。
- 5 个异常用例通过；包含准备、查询检查和清理的 13 个请求共通过 18 项断言。

### 资源不存在

## 复跑方法

1. 启动本地服务，在 Postman 选择“本地预约服务”环境，确认 `base_url`、`username` 和 `password`。
2. 分别运行正常流程、输入校验、鉴权异常、资源不存在四个分类，迭代次数设为 1。
3. 鉴权异常分类包含有效鉴权、创建预约、操作前查询、五个异常请求、四次操作后查询及最终清理，共 13 个请求。
4. 资源不存在分类依次运行有效鉴权、创建、成功删除、不存在编号的查询、更新和删除，共 6 个请求。
5. 更新与删除鉴权异常请求按场景不发送 Cookie 或发送无效 Cookie；资源不存在的更新、删除使用有效 Cookie。
6. 依据新的 Runner 结果更新用例表、报告与 README 统计，并替换对应分类的汇总截图。

完整配置与执行顺序见 [测试用例与执行记录](TEST_CASES.md)。服务重启会清空 token 和预约；每次复跑通过分类内的准备请求获取有效凭证并创建新的测试数据。

## 结论与验证范围

本次已完成正常预约流程、五种输入错误、五种鉴权异常及三个资源不存在场景，22 个计划用例全部符合本地服务约定。已验证未授权更新没有改变被检查的预约字段，未授权删除后预约仍存在，已删除预约无法查询、更新或再次删除。

本报告的结论对应这 22 个用例及当前本地服务实现。`/ping`、性能与并发、日期合法性等不在本次用例范围内；报告中的响应时间是本机运行记录。
